# 최신 실험 조건표 적용과 예비측정

## 코드에 반영한 네 가지 변경

| 변경 | 실행에 적용한 내용 |
|---|---|
| 세 구성 비교 | all-pass(9001 수신 CPU1), pass-xsk(PASS/PASS/AF_XDP, CPU3), mixed(PASS/CPUMAP/AF_XDP, CPU3) |
| C의 위치 대조 | 워커 3개를 유지한 CPU0,1,2→0,2,3 이동과 PASS 수신기만 CPU3 이동을 별도 실행 |
| 구간 분석 | 같은 패킷의 보정된 HW 시각을 d₁과 총지연에서 재사용하고 구간 합 대조 |
| 실행 범위 정리 | 중간 부하 3행 삭제, 중복 조건 재사용, 단독 15회 + 본실험 120회 |

실행표는 15조건이며 조건마다 5/10/15회가 배치된다. A·B는 중복을 제외한
10조건에서 all-pass/mixed 각 5회, 무부하·복합부하 두 조건에는 pass-xsk 5회를
추가한다. C 두 조건은 mixed만 5회씩 수행하고 기준 결과를 A에서 가져온다.
단독은 mixed의 활성 흐름 하나씩 총 3조건 × 5회다.

60초 측정, 부하 안정화 5초, 중요 흐름 각 1,000PPS, 중요 흐름 기한100µs,
반복5회는 유지한다. 메모리·I/O·ON/OFF 부하와 CPU2 단독 부하 대조는 추가하지 않는다.

## 기본 CPU·정책 배치

| 역할 | 송신 Pi | 수신 Pi | 정책·우선순위 |
|---|---|---|---|
| 일반, 9000 | CPU0 | CPU0 (C 수신기 이동만 CPU3) | OTHER/0 |
| 중요1, 9001 | CPU1 | all-pass CPU1 / pass-xsk·mixed CPU3 | FIFO/80 |
| 중요2, 9002 | CPU2 | CPU1 | FIFO/80 |
| iperf3 | CPU3 | CPU0 | OTHER/0 |
| 관리·관측 | CPU3 | CPU0 | OTHER/0 |
| NIC IRQ | 기존 설정 | CPU2 | 실제 정책·우선순위 기록 |
| CPU 부하 | 없음 | 기본0,1,2 / C 워커 이동0,2,3 | OTHER/0, 워커3개 |

`receiver_cpus`는 mixed/pass-xsk의 수신기 배치다. 생성기가 추가하는
`flow2.all_pass_rx_cpu=1`은 all-pass에만 적용한다. `run.json`과 placement 기록에는
해당 mode에서 실제 사용하는 CPU가 남는다. 두 Pi는 같은 설정 파일을 사용하고
각 역할의 `supervisor_cpu`·`network_cpu`를 읽는다.

## 예비시험에서 확정할 값

1. **P03 전달 동작:** FIFO80 출발 설정에서 중요 패킷 수신과 IRQ·CPUMAP 스레드
   상태를 본다. 전달이 밀리면 CPUMAP FIFO85를 같은 부하로 비교한다. 선택한
   정책은 본실험의 모든 해당 run에 동일하게 적용한다. 현재 helper는 정책을
   기록하며 변경은 별도 설정 단계에서 수행한다.
2. **P02 배경 전송률:** 단방향 UDP 1스트림을 단계당10초 측정해 기준R을 정하고
   `network_high_bps=0.9R`를 입력한다. 중간50% 전송률 항목은 삭제했다.
3. **P01 일반 PPS:** 중요 흐름 각1,000PPS를 유지하고 일반0/1,000/3,000/9,000PPS
   후보를 시험한다. 실제 송수신·지연·손실을 보고 `pass_high_pps`를 정한다.
   선택한 최고값이 9,000을 대체하며 모든 비교 구성에 동일하게 사용된다.
4. **종료 대기:** 높은 부하에서 수신 대기를 늘려 수신 수·꼬리 표본이 안정되는
   `settle_ms`를 정한다. `drain_ms=100`과100µs 기한은 유지한다.

실행 profile에서 null로 남긴 값은 network_high_bps, pass_high_pps, settle_ms다.
IP와 장치별 배치는 실제 실험망에 맞춰 작성한다. 기존 네트워크 진단 수치를
ACE 혼합 경로의 예비측정 값으로 자동 대입하지 않는다.

## 생성 → 검증 → 실행

```bash
# 초안만 생성
python3 experiment/design/build_plan.py --output /tmp/ace-plan-draft

# profile.example.json을 복사해 예비측정 값을 채운 후, 새 폴더에 생성
python3 experiment/design/build_plan.py --profile /path/profile.json --output /tmp/ace-plan-final

# 장치 설정을 바꾸지 않는 native 조건 검증
./experiment/ace-run plan --config /tmp/ace-plan-final/main-01.conf

# 같은 계획 폴더를 두 Pi로 복사한 뒤 각 장치에서 실행
sudo ./experiment/run_matrix.sh receiver --plan-dir /tmp/ace-plan-final
sudo ./experiment/run_matrix.sh sender --plan-dir /tmp/ace-plan-final
```

위 마지막 두 명령은 각각 수신·송신 Pi에서 실행한다. `--d01-d11`은 같은 최신
설계를 생성하는 호환 옵션이다. 이전 계획은 재사용하지 않고 새 폴더에 생성한다.
wrapper는 execution.json의 조건 순서를 따르며 설정 해시·예정 구성·반복 수를
검사한다. 두 모드는 반복마다 교대하고 세 모드는 시작 위치를 순환한다.

## P04 본측정 전 60초 리허설

- 실제 송신PPS·송수신 수·손실·유효 지연 표본 수를 집계한다.
- ingress_update_error, cpumap_update_error, overflow_packets를 검사한다.
- 동일 패킷의 총지연=d₁+d₂+d₃ 및 보정 시각을 확인한다.
- 수신 측정 구간 CPU 평균과 scheduler-ready.json을 결과에 남긴다.

기본 최고 후보의 목표 기록은 (9,000+1,000+1,000)×60=660,000개다.
생성기와 native parser는 1,048,576개 기록 한도를 함께 검사한다.

보존한다. 최신 실행·수집 방법은 [실험 README](../README.md)에 있다.
